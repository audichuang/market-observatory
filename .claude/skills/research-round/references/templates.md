# 研究回合通用範本

依 SKILL.md 的相應步驟選用下列範本；尖括號欄位由主控依本輪範圍填入，再交給各角色。

- [研究者](#研究者)：共用作答規則、面向任務與摘要格式。
- [查核者](#查核者)：非作者的逐條查核任務。
- [反方審查](#反方審查)：方向複查與獨立反駁。

來源：`web/docs/research-2026-10-28/parts/_context.md`「作答規則」「輸出格式」、`web/docs/research-2026-10-28/prompts/V-J.md`、`web/docs/research-2026-10-28/parts/_review-common.md`。不沿用舊輪的使用者背景、名額、日期、工具競用限制或模型設定。

## 研究者

將以下作答規則寫入本輪 `parts/_context.md`，前面補使用者原話、決策問題、現有功能、現行立場與排除清單。立場與排除清單附現行 forecast 章節及上一輪 report「刻意不做的事」的定位；範圍登錄不是計算授權。

```text
作答規則
1. 每個數字附日期與一手來源網址，網址去追蹤參數。打不開一手來源時標「未核實」，說明實際看到的是摘要、節錄或二手轉述；不可假裝讀過全文。
2. 每個「有效／有預測力」主張只標一個證據等級：none／bank_claim（機構自述、無樣本外檢驗）／anecdotal／academic_is（學術、僅樣本內）／academic_oos／independently_tested。另標結果正／零／負，寫明期限、資產、是否橫斷面選股、成本與可外推範圍。
3. 負面與無效結果同樣有價值。與排除清單重疊時只寫新證據或與既有結論的差異；文獻不足寫「未找到」，交代找過的範圍。
4. 不對任何市場歷史資料跑新的回測或探索統計，包括順手算條件發生率。需要的新數字只能引用文獻或已存在的結果；值得做的新計算寫成「建議事前登記的計算」，列定義、target、資料、待登記門檻與決策用途，不執行。既有門檻與名額引用 forecast 章節。
5. 只寫指定的唯一輸出檔。不改程式、不改登記、不 git commit、不部署、不寫正式站或呼叫 /api/admin/*。可少量唯讀確認公開端點；查來源不能順便跑市場統計。
6. 用繁體中文；論文標題、代號、API 與技術詞保留原文。程式位置用 repo 相對路徑加行號，親自開檔確認。

面向任務（寫在 parts/<ID>.md）
- ID 與摘要建議前綴：<ID>
- 決策問題：<本面向要回答的具體問題>
- 查核範圍與排除：<只查哪些新地方、既有結論的定位>
- 唯一輸出檔：<研究目錄絕對路徑>/results/<ID>-<slug>.md

輸出格式
完整研究寫進唯一輸出檔，最後一節固定為：
## 給整合者的摘要
### 關鍵發現
3–8 條，每條附證據等級與來源。
### 對我們 App 的建議
| ID | 建議 | 服務哪個決策 | 證據等級 | 成本（低／中／高） | 需事前登記？ | 與既有規則或排除清單衝突？ |
### 建議不要做的事與理由
### 未核實、不確定、需要人判斷的地方

「服務哪個決策」用本輪 context 的決策名稱，或資料／流水線／呈現；不沿用舊輪的決策代碼。最後回覆只附輸出檔路徑與整節摘要原文；主控保存原始回覆到 logs/。
```

## 查核者

每份結果另派非作者查核，把以下內容寫成 `prompts/V-<ID>.md`；補上本輪共用的禁止計算與唯一寫入限制。

```text
# V-<ID>：獨立查核
你是查核者，不是作者。先讀 <研究 prompt 路徑> 與 <研究結果路徑>。LLM 研究是二手材料，引用、數字、網址與行號都可能錯；沒親眼看到就不算核實。

1. 從「給整合者的摘要」抽最多 15 條建議所依賴的關鍵主張。優先查高優先建議、精確數字、自稱已核實或意外的結論。
2. 每條親自打開一手來源或現行 source；記下實際看到的短引文或行內容。判定：已核實／部分（主旨對但細節或閱讀範圍不足）／被推翻／無法核實（找不到或打不開）。「另一個 agent 驗過」不算證據。
3. 程式主張要找反證：有沒有攔住該 bug 的程式碼？觸發輸入是否成立？只用 source 或合成輸入查證；不跑市場歷史統計。
4. 每條建議對照現行 forecast 的事前登記章節與上一輪 report「刻意不做的事」，列規則衝突或重開已否決項目。
5. 找出證據高估（機構自述被寫成獨立驗證、樣本內寫成樣本外、橫斷面證據外推指數擇時），並寫最重要的遺漏。

只寫 <研究目錄>/verify/V-<ID>.md，繁體中文：
1. | # | 主張（短述） | 原報告位置 | 判定 | 實際看到 | 來源網址或檔案:行號 |
2. | 建議 ID | 衝突的規則 | 說明 |
3. 證據等級高估清單
4. 最重要的遺漏
5. 應降級、刪除或保留的建議與理由

最後回覆：輸出路徑、四類判定各幾條、被推翻的主張清單、第 5 節原文。主控保存原始回覆到 logs/。
```

## 反方審查

主控將以下共用任務與各視角問題組成 prompt，分派 R1 證據與規則紀律、R2 工程可行性、R3 使用者價值。每位取得本輪 context、report、results、verify、規則與排除清單的位置。

```text
你是反方審查者，找方向哪裡錯、哪裡漏、哪裡排錯優先序，不是潤稿。每條結論應可回到研究、查核或現行 source 找到依據。需要時親自讀一手來源；不重做研究、不跑市場歷史回測或探索統計。

視角：<R1／R2／R3 與該視角的問題>
唯一輸出檔：<研究目錄>/review/<R-ID>-<slug>.md
只寫該檔，繁體中文，不 commit、不部署、不寫正式站。

輸出：
1. 總評：方向能否執行、最大問題。
2. | # | 嚴重度（高／中／低） | 報告位置（章節與條目） | 問題 | 證據（檔案:行號或網址） | 具體改法 |
只列有證據的 finding，同根因合併。無 finding 的範圍列出已檢查的來源與結果。
3. 檢查過的範圍清單。
最後回覆：輸出路徑、總評與 Findings 表原文；主控保存原始回覆到 logs/。
```

每條 finding 的獨立反駁任務另派給未寫報告、未提出該 finding 的代理：

```text
試著推翻 <finding ID 與完整內容>。親自讀其引述來源與報告上下文，找出保護條件、反例、既有限制或與根因不符的證據；不要只同意審查者。
遵守同一份禁止市場計算與唯一輸出限制，只寫 <研究目錄>/review/<finding-ID>-rebuttal.md。
回覆：可推翻／部分成立／仍成立、實際所見與來源定位、成立範圍、建議處置。主控逐條把證據、判定及改到哪裡寫進 report，不成立的 finding 也保留處置紀錄。
```
