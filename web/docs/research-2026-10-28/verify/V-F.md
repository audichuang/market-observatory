## 3. 證據等級高估清單

- **FinMem：需降的是最終系統的 OOS 解讀（查核 #14）。** 原報告 :113 有保留 LLM cutoff 疑慮，但沒有指出已讀到的「依測試表現選 backbone」及期間重疊。對經該程序選出的最終設定，保守採用判斷應降為 `academic_is`，註明有作者宣告的時間切分、正結果、單股每日交易，但另有測試期參與設計選擇。不能把這一判定擴張為每個預先固定設定都已證明無效。[原文 §6.1](https://arxiv.org/html/2311.13743v2)
- **RD-Agent：論文聲稱的 OOS 與公開搜尋流程須分開（查核 #15）。** 日期切分能核實；主結果是中國股票橫斷面排名／投組，並非 SPX 21 日方向或 dd5。指定程式有 test 回測指標進入研究 feedback 的路徑，對這個反覆選擇後的結果應按 `academic_is` 處理。論文結果只能寫「作者聲稱 `academic_oos`、正；完整搜尋與 test 隔離未核實」，不宜在摘要只留無限定的 `academic_oos，正`。當年論文的精確執行版本未重建，因此不宣告其全部跨市場／較晚期間結果都已被推翻。[論文 §2.5、§3](https://arxiv.org/html/2505.15155v2)、[公開 feedback 程式](https://github.com/microsoft/RD-Agent/blob/484776c211e4fbbeef03e0ec00d6bbee7362a4f4/rdagent/scenarios/qlib/developer/feedback.py#L70)
- **六條採用建議本身沒有被寫成已證實有效。** F-01～F-06 全標 `none`，且原報告 :300 未頒任何專案 `independently_tested`；沒有看到把 bank_claim 升為獨立檢驗的情況。Dexter 的 judge、標準 JSON 解析及原始碼缺陷是工程證據，不能升格為投資或內容品質改善的效果量。原報告大致守住這點；F-06 仍須靠人工金標盲評證明價值。

## 4. 最重要的遺漏

最重要的遺漏是沒有沿「評估結果→選設定／選新假設」追到底，確認測試資料是否真的隔離；原報告花力氣查了資料輸入 PIT，對研究者與 agent 使用績效回饋的污染卻只留下概括疑慮。FinMem 原文明示用測試表現選 backbone；RD-Agent 同一指定 commit 也可追出 test 回測指標經 recorder→exp.result→feedback 影響下一個假設及最佳結果替換。這些比「存在 train/valid/test」更能決定證據等級。後續若補查，應索取對應論文執行 commit、完整搜尋／選擇紀錄、feedback 所用期間及最後凍結後未觸碰的評分紀錄，採文件與程式查核即可，不應為了補這個缺口重跑本專案市場歷史。來源見查核 #14、#15。

## 5. 結論：哪些建議應降級、刪除或保留

- **保留 F-01、F-02，作為優先工程提案。** 本專案的批次留存與事實評估缺口有原始碼依據；效益仍標 `none`。
